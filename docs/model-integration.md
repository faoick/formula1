# Интеграция исходного Blender-проекта

Источник: `FORMULA_1_ENGINEERING_PROJECT/Formula1_Engineering.blend`, Blender 4.5.9 LTS. SHA-256 фиксируется в `public/models/manifest.json`. Экспортёр открывает файл в фоновом процессе, меняет только его копию в оперативной памяти и сохраняет исправленную копию в `artifacts/Formula1_Engineering_Web_R2.blend`; исходный файл не перезаписывается.

## Что экспортируется

Исходные объекты FULL CAR с `part_id` из систем 07–15 и относящаяся к двигателю часть 16. Кузов, колёса, сцены освещения, подписи Blender и дубликаты exploded scene не попадают в браузерный двигатель. Камеры и свет создаются отдельно для WebGL. Никаких внешних моделей не использовано.

Сохранены part_id, name_ru, name_en, description, system, material, function, component_kind, explosion_group и дополнительные кинематические свойства. `export_extras=True` переносит свойства в GLTF node extras. Параллельный manifest обеспечивает удобный индекс без повторного обхода геометрии.

## Оси и иерархия

Blender: X продольная ось, Y поперечная, Z вверх; метры. GLTF: `(x, y, z) → (x, z, -y)`, Y вверх. Исходные матрицы и сведения о родителе записаны в manifest для аудита. В поставленной модели детали не имели сборочной родительской иерархии. Экспорт добавляет группы ASSEMBLY, сохраняя мировое положение каждой детали.

Версия R2 заменяет прежние общие смещения на 35 подготовленных траекторий с этапами. Исходное поле `explosion_group` сохранено для каталога; `assembly_key` задаёт фактическую сборку, а `trajectories` — вектор и интервал её движения. Оба банка разделены, поршни выходят по осям цилиндров. Подробности и проверенные зазоры: [revision-r2.md](revision-r2.md).

## Оптимизация

Сохранены все детали. Bevel ограничен двумя сегментами, subdivision — первым уровнем, кривые — шестью продольными шагами на сегмент и двумя уровнями скругления. Модификаторы применяются только для экспортной геометрии. PBR-цвет, металл и шероховатость сохраняются; процедурные сети Blender не воспроизводятся бит-в-бит.

`artifacts/engine.source.glb` — переносимый несжатый исходный экспорт. `engine.glb` — meshopt-сжатие с дедупликацией буферов и общих meshes, без merge/join узлов. Имена и extras остаются. Декодер поставляется в JS-пакете, внешнего CDN нет. Повторный запуск заменяет те же файлы и не накапливает объекты.

## Подключение обновлённого источника

Запустите команды README. Обязательны сцены FULL CAR и ENGINE EXPLODED VIEW и приведённые custom properties. Затем запустите validate:model и браузерные проверки. При переименовании сборок обновите `presentation_revision.py`, `assemblyTimeline.ts` и `cinematicShots.ts`. При изменении размера деталей перепроверьте крупные планы. Для другой архитектуры двигателя рабочий цикл требует новой кинематической схемы.
